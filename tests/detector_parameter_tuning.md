# Detector 参数调试（2026-10-12）

## 最新变更：取消边缘轮廓过滤

按用户要求，已删除 `detect()` 中根据 `boundingRect` 排除触边轮廓的条件。触边灯条继续进入形状筛选和配对；对应测试改为允许合格的触边灯条配对。`image_1.jpg` 顶部的红色背景条纹也会重新形成配对，因此移除依赖边缘过滤的该项背景拒绝断言，保留其余检测与 PnP 检查。以下为此前保留边缘过滤时的调参记录，样本指标不代表当前版本。

另按用户要求删除 `detector` 类的全部 `constexpr` 成员，原数值直接写在函数默认参数和 `detect()` 的阈值表中，参数值不变。

针对实时摄像头同时存在漏检、背景误检的问题，使用仓库两段完整视频、11 张红蓝样本图，以及变暗、缩小、背景裁剪和相反颜色检测进行离线比较。没有采集本次实时摄像头画面，因此下面的改善只覆盖这些样本。

## 此前调整

当时参数集中在 `include/lightbar_detector.hpp`，`detect()` 使用相同的默认几何参数：

| 项目 | 原生产参数 | 此前调参值 |
| --- | --- | --- |
| 高亮检测：目标通道与对立通道差 / 目标通道亮度 | 70 / 170 | 70 / 170 |
| 无匹配时低阈值补检 | 无 | 40 / 100 |
| 最小灯条轮廓面积 | 40 px² | 12 px² |
| 最大上下错位 / 平均灯条长度 | 0.8 | 0.5 |
| 最低配对分数 | 0.35 | 0.40 |
| 接触图像边界的灯条 | 参与配对 | 排除 |

最小灯条长宽比仍为 1.5、最大灯条长度比仍为 2、角度差上限仍为 20°、配对宽高比仍为 0.8–3.1。过度收紧长度比会漏掉真实蓝板，未采用。

高亮轮廓先检测，成功后直接返回；只有没有任何配对时才执行低阈值补检。直接在整张图统一降低阈值会扩大亮灯光晕，在视频 1 上净丢失 25 个有检测帧，因而没有使用该方案。两遍结果不合并，不会用补检替换已有高亮配对；如果已有一个高亮配对，同时存在另一个暗板，该暗板不保证被补检。

排除接触边界的轮廓，是因为其真实端点不可见，容易将背景竖条配成板，也会使 PnP 长度失真。代价是画面边缘的真实截断板也不参与检测。补检增加无匹配帧的计算量，未在实时摄像头上测量新增耗时。

## 结果

下表的“有检测”仅表示至少一个配对，不是人工完整标注后的召回率；检测数量增加不能直接解释为识别精度提高。

| 数据 | 原参数 | 当前参数 |
| --- | ---: | ---: |
| 视频 1 有检测帧 / 815 | 713 | 722 |
| 视频 2 有检测帧 / 351 | 351 | 351 |
| 11 张原图有检测 | 10 | 10 |
| 原图亮度乘 0.6 后有检测 | 0 | 7 |
| 原图宽高各缩小一半后有检测 | 5 | 10 |
| 11 张相反颜色测试出现检测的图片 | 1 | 0 |
| 11 张上方 45% 无装甲板裁剪出现检测 | 0 | 0 |

人工查看了原图、暗图、缩小图及相反颜色结果。明确消除的误检是 `image_1.jpg` 顶部被截断的两条红色背景竖条；不代表所有同色背景误检都已消除。变暗和缩小是人工变换，没有模拟真实曝光改变、噪声、失焦和运动模糊。样本参与调参，不是独立测试集。

初筛扫描颜色、亮度、面积、长宽比、长度比、错位、角差和分数候选，视频每五帧取一帧；最终候选 25 与基线在完整 1166 帧上比较，并把每张图/每帧的数量、全部角点与生产 `detector::detect()` 对照（角点容差 1e-5 px），全部一致。

## 复现

在配置好 OpenCV DLL 路径的 PowerShell 中执行：

```powershell
cmake --build tests/build --config Release --target detector_tests detector_parameter_evaluation
.\tests\build\Release\detector_parameter_evaluation.exe . tests/outputs/detector-tuning/verified 1 finalists
.\.venv\Scripts\python.exe -B -m tests.summarize_detector_parameters --directory tests/outputs/detector-tuning/verified --render-video
ctest --test-dir tests/build -C Release -R '^detector_regressions$' --output-on-failure
```

去掉末尾 `finalists`、将步长设为 `5` 可重做全部候选扫描。候选 0 为原生产参数，23 为单遍低阈值，24 为单遍高阈值，25 为最终高亮优先/低阈值补检策略。
